# 中继银行退役:命令变方法,策略变守卫

## Context

ViewerWidget 的"遥控面板"架构:~14 条纯转发信号(zoom×4/scroll×4/fit×3/lock×2)经 `setInteractionEnabled` 的 connect/disconnect 银行接到 ImageViewerV2——**接线即状态**。三重门禁互不一致(银行剪线 / MW 的 interactionEnabled 检查仅 fit / viewer 内部检查仅右键菜单),过滤器/网格命令在 crop 中仍可用,lock 两条只接不断(每次进出 crop 叠一层重复连接)。用户反馈该架构理解困难,强烈怀疑需重构——怀疑成立:它把三个正交关注点(命令路由 / 输入策略 / 事件反馈)拧在一根会断线的总线上。

探查确认的守门真相:`setInteractionEnabled(false)` 期间缩放中继物理断开(这是 crop 几何不失联的真正保障),但 filter/grid/lock 从不剪——即现有行为 = **银行内命令禁用,银行外命令照常**。新架构必须逐字保持这张行为表。

## 目标形态

**命令 = ViewerWidget 上的方法,策略 = 方法内单点守卫,反馈 = 保持信号。**

```cpp
// ViewerWidget(所有画布命令的单一门面)
void ViewerWidget::zoomIn() {
    if(!canvasInputEnabled) return;      // 策略:单点、可见、可局部豁免
    imageViewer->zoomIn();
}
```

- **受守卫命令**(13):zoomIn/zoomOut/zoomInCursor/zoomOutCursor、scroll×4、fitWindow/fitWidth/fitOriginal——crop 期间禁用,与现状逐字一致
- **不受守卫**(与现状一致):setFilterNearest/Bilinear/setScalingFilter、toggleTransparencyGrid(今天在 crop 中就可用)、toggleLockZoom/View(今天也可用,且重复连接 bug 随银行一起死)
- **反馈信号保留**:scalingRequested、draggedOut(连接改为 ctor 常驻,不再被剪——crop 期间 overlay 捕获鼠标,拖拽本就不会发起)、playbackFinished、showScriptSettings、scaleChanged
- **`setCanvasInputEnabled(bool)`**(原 setInteractionEnabled 更名,语义诚实):翻转守卫标志 + 保留两个真实副作用(WA_TransparentForMouseEvents 鼠标门、hideContextMenu)
- **程序化设模式不走守卫**:ViewerWidget::setFitMode 现在经银行 emit fit 中继(274-281)——改为直呼 `imageViewer->setFitWindow()` 等;守卫只拦用户命令,程序化设置(模式持久、程序触发的 fit)不受 crop 影响

## 变更面

**viewerwidget.{h,cpp}**
- 删 13 条命令中继信号(toggleLock×2、zoom×4、scroll×4、fit×3)+ draggedOut 的银行内 connect;ctor 里 4 条过滤/网格中继连接删除(命令变方法后由 MW 直调)
- 同名方法:每条一守卫一直呼;`setFitMode` 内部直呼 imageViewer 的 setFit*
- `setInteractionEnabled` → `setCanvasInputEnabled`,体 = 标志翻转 + 鼠标透明 + hideContextMenu
- interactionEnabled() getter 保留(showContextMenu 内部检查用它)

**mainwindow.{h,cpp}**
- 删 21 条纯转发/直呼槽:zoom×4、scroll×4、pauseVideo、seekVideo×2、frameStep×2、toggleMute、volumeUp/Down、toggleTransparencyGrid、toggleLock×2、setFilterNearest/Bilinear、setInteractionEnabled(死代码,全仓库零调用)
- 保留组合槽(fit×3 带"Zoom temporary disabled"消息与门——调用 `viewer->fitWindow()`,viewer 侧守卫是第二道硬闸,职责分离有注释)、cycleFitMode/switchFitMode(视频拦截逻辑)、setFilter(ScalingFilter)(带消息)、showContextMenu、toggleScalingFilter
- 新访问器 `ViewerWidget *viewer()`(与 shell()/overlays()/dialogs()/crop() 对齐)

**core.cpp**:约 21 条 ActionManager 连线改指向 `mw->viewer()` 的方法(R12 正则 `&ActionManager::<name>,` 原地不动;fitNormal→`&ViewerWidget::setFitWindow` 等映射保持)

**cropcontroller.cpp**:两处 `viewer->setInteractionEnabled(...)` → `viewer->setCanvasInputEnabled(...)`

**DocumentWidget**:不动(`setInteractionEnabled` 只门缩略图悬停,唯一活调用方是其构造函数;MW 侧死代码删除后语义更清楚——那个名字曾让两套不同机制共用一个词)

## 不变量(测试即行为表)

- `fitOriginalPersistsAndArrowsStayInInspectMode`:检查层 Left→scrollLeft 必须照常平移(经新方法路径),浏览模式 Left 照常翻页
- `cropEntryRespectsTheUserZoom`:进 crop 不动 zoom/mode(本来就无 fit 调用,新代码连守卫翻转都更简单)
- `cropPanelSurvivesAnEarlyTrigger`:早期触发 + 进出各一次(旧 bug 的重复 connect 在新架构中不存在)
- `slideshowLifecycleRequestsLoopPlaybackOffThenOn`:MW::setLoopPlayback 信号与转发保留(Core 在 mw 上 emit + QSignalSpy 钉住)
- R12:所有 `&ActionManager::<name>,` 连线留在 core.cpp;R11 漏斗不动;fitModeChanged 已是 QProperty 观察(上一轮),本轮不再动
